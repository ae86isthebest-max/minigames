# 製作檢查工具（不是遊戲的一部分）

先在 `detective/` 開一個本機伺服器：`python3 -m http.server 8765`，再用 node 執行（需要 playwright）。

- `lint.js`：兩集的資料檢查。問題／證物引用的 id 是否存在、每樣東西有沒有區域、每個區域有沒有東西、每天的時間夠做多少。最後會列出每條推理題「看到哪一樣線索就會出現」，要人工確認每一樣單獨都足以知道題目的前提。
- `lint2.js`：「出示……」的問題有沒有設前提、哪些證物會過期。
- `arr.js`：只靠畫面箭嘴，能不能走到每一個區域。
- `arctest.js`：跨集記憶（arc.js，主線用）：這一集查到、下一集記得，前情提要兩個版本。最後要印出 ARC TEST PASS。
- `slots.js`：三個存檔位（arc.js 的 SLOT）各自獨立、舊進度變成存檔 1、刪除只刪那一個；換存檔要先確認（`slotUse` 是 async，腳本裡要 `await`）；存檔碼（`SLOT.code`／`SLOT.load`）匯出再還原內容一樣、亂貼的碼不會弄壞進度。最後要印出 SLOT TEST PASS。
- `balance.js <案件編號> [設定]`：多日案件的平衡統計。每天「全部做完要幾分鐘 ÷ 那天有幾分鐘」（一定要 ≤ 2，目標 ≤ 1.8）、每個人當天問得到幾題、照正常玩法一輪看得到多少。標準：每個人每天肯回答 6–10 題、至少是當天問得到的一半；時間至少夠做完一半。可以用第二個參數試別的數字，或用 `"from":n` 模擬「玩到第 n 天才換新規則」的舊存檔。
- `glint.js`：走近才閃（world.js 的 nearYou／glint：還沒看過的證物和小細節，只有主角在同一個區域或 40 格內、同一層樓才閃）、小東西的點擊範圍（至少一根手指大），以及人擋在東西前面的情況（閃光畫在人上面，並移到沒被擋住的位置；點在人身上＝找人，整個被擋住的東西先看東西），還有畫面下面的「🔎 附近」清單（列的就是會閃的那幾樣；點名字＝點那樣東西；名字用 label／name／title，要中性、不劇透）。最後要印出 GLINT TEST PASS。
- `playx.js`：`CASE=<集的 id> node tools/playx.js`，不限時間找死內容，再照真正的時間和題數玩一次要拿到 S；`FLAGS=a,b` 先設好前面幾集留下的主線旗標（以前的 `_playx_flags.js` 現在就是它，舊指令照用）。要等到某個時間的事件以後才做得到的問題、證物、化驗都會等到那個時間再試。
- `scenesheet.js` 的 mode：`all`（全部當成看得到）、`open`（地點房間全開，但證物和小細節照真正的條件，還看不到的不會閃）、`fresh`、`last`、`days`；`ONLY=地點,地點` 只拍幾個地點。
- `outscenes.js <輸出.png>`：戶外場景總覽。每一集用 `WK.autoWorld` 排出來的戶外場景（`OUT0`＋`C.outScenes`）畫成一張對照圖：紅線是人站的那條線（圖上 y=98），黃框是可以點的範圍，洋紅色是會被去掉的天空。新畫或改過戶外場景都要看一次：牆腳、門、桌椅、盆栽要落在地面上（地面要蓋到紅線，東西不能停在半空或站在山上），黃框要框在畫出來的東西上，房子旁邊不能留下一塊沒去掉的天空（天空的漸層顏色要一直偏藍：藍 ≥ 紅）。每一天畫出來不一樣的（晚上、下雨）各畫一格。**海、遠山、牆不可以變成洋紅色**：`WK.noSky` 只挖「從最上面一路接得上」的天空顏色，忽然變暗或變成別的顏色的一大片（海、山、牆）會留著；招牌、屋簷正下方那一小塊天空會從旁邊補挖（被框住、跟天空同色的窗戶不會動）。文字輸出的 `LEFT n`＝還有 n 格跟天空同色的地方沒去掉，是窗戶就沒事。自動判斷不準時（例如晚上、天空是單色、海又比天空亮），在那一集寫 `skyTo:{ 場景名: 第幾排 }`，從那一排開始一律不挖。
- 背景（`EPn.setting = { 地點: "town"｜"city"｜"village"｜"villa"｜"coast" }`）：`coast`＝海邊，遠方只有海平線和低低的岬角，沒有高樓。**場景自己畫了海、看得到海平線的地點都用 `coast`**（不然海平線上會冒出大樓）。海平線的高度和海的顏色會自動跟這個地點的戶外場景對齊（比場景挖掉的天空低、用場景自己的海色，陰天晚上一樣染色）。改完用 `ONLY=coast node tools/scenesheet.js <輸出> <集> <集> days` 每一天都看一次。
- `backup.js`：自動備份（arc.js 的 BACKUP），用假的 `window.claude` 模擬試玩卡的雲端資料：備份上去、儲存空間不見了自動拿回來、備份比較多時先問、自己刪的不會跑回來、連不上不當機、網站版安靜略過。最後要印出 BACKUP TEST PASS。真的試玩卡要宣告 `capabilities:{ db:{}, user:{} }` 才有備份；有沒有開到，看首頁存檔列是不是寫「☁ 自動備份開著」。
- `rq.js`：推理題一打開就算一次機會（平常蓋著、離開再蓋起來、第一次全對才有 S）。最後要印出 RQ TEST PASS。
- `ep1.js`、`play2.js`：照最佳路線玩第一、二集，要拿到 S。
- `poses.js <輸出資料夾>`：人物動作總表（poses-front / poses-hands / poses-side.png）。改了 pixel.js 的人物就跑一次，用眼睛看：每個動作左右手、面向左右對不對，放大以後有沒有變形。
- `animsheet.js`：重播／監視器動畫的逐格總表。`CASE=案件id node tools/animsheet.js <輸出資料夾> [動畫id或場景名|-] [每段幾格=4] [每格寬=288]`，
  環境變數 `BEATS=4-7` 只看其中幾段、`CROP=x,y,w,h` 放大一小塊（192×108 的座標）。一列是一段字幕，由左到右是這一段的 12%、40%、68%、97%。
  每一段都要用眼睛對：動作和字幕／證物對不對、用哪隻手、有沒有沿著樓梯一級一級走、人有沒有穿過桌子或屍體、進門是不是背面走進去。
  某一段有 `scene`（換場景）的話，左上角會印出場景名。也會自動警告：打錯的姿勢／物件名字、斜著走卻沒有宣告 `stairs`、直上直下卻沒有宣告 `ladders`。寫法見 pixel.js 的「姿勢字串」和 PX.play 的說明，第 1、2 集（case1_art.js、case2_art.js）是範例。
- `scenesheet.js <輸出資料夾> [從第幾集] [到第幾集] [all|fresh|last]`：全部走動畫面的對照圖。每一集、每個地點、每個區域（房間、戶外、二樓、暗格、街上）各拍一張，主角站在遊戲裡走進去會站的位置。
  用眼睛看：東西有沒有停在半空／陷進地面、門有沒有被切掉、人有沒有疊在一起、主角有沒有擋住人。`COLS=5 CELL=384 PER=25` 可以一張看一整集。寫完新的一集一定要跑一次，一張一張看。
- `groundlint.js [輸出檔名] [從第幾集] [到第幾集]`：室內場景自動檢查。把每個房間的圖跟「只有牆和地板」的圖比，找出：FLOAT＝東西的底離地板線 2–10 格（浮在半空，或者被最後才畫的 floor() 蓋掉下半截）、
  EMPTY＝可以點的範圍（證物／小細節的 hot）裡面什麼都沒畫、OUT＝範圍超出畫面。看過確定沒問題的寫進檔案裡的 OK 清單。最後印 `GROUND LINT PASS` 或還有幾個要看。
  畫室內的規則：家具的底要剛好碰到地板線（`floor(y)` 的 y）；`floor()` 如果放在最後才呼叫，地板線以下的東西全部會被蓋掉，要畫在地上的東西（鞋、垃圾桶）要寫在 `floor()` 後面。
- `maplint.js [輸出資料夾] [從第幾集] [到第幾集]`：地區地圖檢查。五種螢幕大小、每一天，地點名牌有沒有被地圖的邊切掉（OUT）、互相蓋住（OVERLAP）、蓋住別的地點的小房子（COVERS）。
  名牌由 index.html 的 `fitMapLabels()` 自動挪開，所以新的一集只要 `C.mapPos` 不要把兩個地點放在同一點就會過。最後印 `MAP LINT PASS`（直拿手機、地點很多的那一集可能剩一兩個，可以接受）。

- 畫面上的小字（櫃子標籤、門牌、紙箱編號）：`fillText` 在 6px 以下會糊。用 `PX.prim.tiny("ZD-7", x, y, 顏色)`：3×5 的像素字，(x, y)＝左上角，每個字佔 4 格寬、5 格高，回傳整串字的寬度（要置中就先算寬度）。
  只有 A–Z、0–9 和 `- . : / + # % ? !`，小寫會自動變大寫，沒有的字（包括中文）會留空。中文招牌還是用 `sign()`。
- 結案畫面（`vCourt`）：`who` 裡的人由 x=44 平均排到 x=178（只有一個人就站 114）。人是 1.4 倍大，站到 178 以後會被畫面右邊切掉，不要改回去。

- `optorder.js [截圖資料夾]`：推理題選項和「誰」的清單「只打亂顯示順序」的檢查。最後印 `OPT ORDER PASS`，也會印出正確答案顯示在第 1–4 格各幾次（要大致平均）。
  規則（index.html 的 `optOrder(i)`、`whoOrder(list)`）：畫面上的順序由「集的 id＋第幾題／人的 id」算出來，每一題固定一種排法，不是每次打開都不同；
  `pickReason(i, j)` 的 j、存檔、結果頁用的都還是資料裡原本的編號，所以**已經上架的集不要為了換位置去改 `options` 的順序**（舊存檔的答案會對錯題）。
  開頭是「看不出來／分不出來／查不出來／不知道／沒辦法判斷／無法判斷」的選項固定排最後。題目寫 `fixed:true` 就照資料裡的順序（例如由小到大的數字）。
  選項的字不要靠位置（不要寫「以上皆是」「前兩個都對」）。`C.kinds`（發生了什麼事）沒有打亂，照資料順序；它用 id 存，要換順序直接改資料就可以。

- `buddy.js`：「這一集的拍檔」設定的檢查，最後印 `BUDDY TEST PASS`。設定寫在那一集的資料上（index.html 的 `BUD()`／`SOLO()`）：
  不寫＝小吳（嫌疑人 id `"wu"`，沒有這個嫌疑人就用預設造型的小吳），跟以前完全一樣；
  `EPn.buddy = false`＝主角自己一個人查：沒有人跟著、右上角是「☰ 選單」、提示和結案的字不提拍檔，劇本裡 `say:["wu", …]` 的話（開場、早上簡報、出事了）改由主角說（名字「你」）；
  `EPn.buddy = { id:"xu", name:"知夏", av:"👩‍🔬" }`＝換一個嫌疑人當拍檔（`say:["wu", …]` 還是「拍檔說」；步驟自己寫了 `name` 的話照步驟的）。
  存檔裡不記拍檔是誰，所以加、改、拿掉都不影響存檔。

- `car.js`：「停在場景裡的車」設定的檢查，最後印 `CAR TEST PASS`。設定（world.js 的 `carOf`）：
  不寫＝巡邏車（白色、有警示燈和藍線），跟以前一樣；`EPn.car = "#7a8a6a"`＝整集都是那個顏色的一般車，沒有警示燈；`EPn.car = false`＝沒有車，到別的地點是從畫面左邊走進來；
  只改一個地點就寫 `EPn.world[地點].car`（顏色或 false），它比整集的設定優先。地圖上的小車跟整集的設定（false 的時候是灰色的車、不閃燈）。
  **開場劇本的 `car:[從, 到, 秒, 顏色]` 如果自己寫了顏色，就照劇本的顏色，不跟設定**（第 1–8、11 集的開場都寫了巡邏車的顏色）；要跟設定就不要寫第四個值：`car:[-60, 8, 2.4]`。
  走動的狀態是按地點 id 記的，同一次開遊戲裡別的集有同名的地點會共用位置，所以停著的車每次進場都會照這一集的設定重新決定。

- `phaseopts.js [截圖資料夾]`：下面六樣的檢查，最後印 `PHASE OPTS PASS`。都是可選的，不寫就跟以前一樣：
  1. `EPn.phaseWord = { unit:"段" }`：一個 phase 不是一天（例如同一天的上午、下午）的時候，畫面上的「今天／下一天／結束今天／每天／隔天／明天早上／N 天」
     會變成「這一段／下一段／結束這一段／每一段／下一段／下一段／N 段」，🌙 變成 ⏭。每個字也可以自己寫：`{ unit, now, next, end, each, later, tomorrow, icon }`（index.html 的 `PW`、`pw()`）。
     引擎裡新增跟「天」有關的字，一律用 `${PW.now}` 這一類或 `pw("整句")`，不要直接寫「今天」。化驗的 `days` 還是「幾個 phase」。
  2. `phases[n].tip`：早上簡報最後那一句（今天幾點到幾點可以調查…）。寫字＝換成這句；`false`＝不說。
  3. `EPn.world[地點].street = false`：這個地點只有室內。沒有「街上」這一區、門口沒有「出去」、沒有停著的車，人和鏡頭都出不了建築（world.js 的 `def.minX`），
     進來就站在第一個房間（`spawn` 不寫＝房間左邊進來 60 格）。只有一個房間、比畫面窄的時候，鏡頭固定在中間，兩邊是黑的。
     房間上面那一條（二樓外牆、窗、招牌）用 `EPn.world[地點].band`：不寫＝照畫；`"sign"`＝沒有二樓（地下室、平房）：不畫窗和屋頂，改成水泥天花板，招牌留著；
     `false`＝只有天花板，招牌和上面的字也不要。只有室內的地點也不會畫雨。
  4. 問題的 `until`：`{ id, q, a, phase:1, until:1 }`＝第 1 段過了以後，還沒問的這一題收起來（不列出來、不算「🔒 還有 n 個問題」、問不到）；問過的照樣留在筆記。
     （第 4 集的 cheng3、第 23 集的 wu2 本來就寫了 `until`，以前沒有作用，現在會照寫的收起來。）
  5. 每次打開案件，走動畫面的狀態（位置、播到一半的開場、停著的車）都清掉重來（`WORLD.resetAll()`），不同集的同名地點（cafe、police、lab）不會互相影響。
  6. 外牆的畫法（街上看建築的時候）：
     `EPn.world[地點].facadeDark = true`＝停電／全暗：外牆的窗一律是暗的（沒有白天的反光、晚上也沒有亮燈的窗），門燈不亮；走進去以後上面那一排窗也是暗的。
     天色、雨、路燈、遠景的樓房不受影響（那些還是看 `worldSky`）。
     `band` 有寫（`"sign"` 或 `false`）＝平房：街上看只有一層，屋頂在一樓上面（`y0:24`、`rows:[88]`），屋頂上面是天空；招牌的位置不變，`band:false` 的時候外面也沒有招牌。
     裡面那一條水泥天花板只有人在建築裡面才看得到（world.js 把「這棟打開了多少」當成 `def.draw` 的第 6 個參數傳進來）。
     `street:false` 而且第一個／最後一個房間是戶外場景：黑色會塗到場景的邊，不會露出一條遠景。
     `EPn.worldSky = ph => [天空上面, 天空下面, 地面 A, 地面 B, 雨, 晚上]`：六格的順序就是這樣。雨＝0 沒有／1 小雨／2 大雨；晚上＝0 或 1（1 的時候窗會亮燈、戶外場景染暗 45%）。

- `hooks.js [截圖資料夾]`：三個接口的檢查，最後印 `ENGINE HOOKS PASS`。都是可選的：
  1. `EPn.world[地點].front = (p, t, op, cam, def) => {…}`：畫在走動畫面所有人前面的那一層（淹到腿的水、霧、鐵窗的影子）。`def.rooms`、`def.pos[房間 id]`（那個房間左邊的 x）
     可以拿來一個房間一個房間畫。畫在人後面的還是用 `drawAfter`。（`labels` 的字是 HTML，在畫布上面，這一層蓋不到字。）
  2. `EPn.world[地點].ext`：從外面看建築的樣子。不寫＝照畫；`false`＝整棟塗黑（山洞、地底：外面什麼都看不到）；`(p, t, op, b) => {…}`＝自己畫（`b.x0`、`b.x1`）。
     有寫的時候外面的招牌字不放。門還是引擎畫（`street:false` 的地點沒有門）。
  3. 房間這一段沒開（房間的 `phase`／`until`／`requires`），裡面的證物就不算可以查：`itemOpen()` 是 false，所以清單、小吳的提示、數目、`inspect()`、
     `balance.js`／`playx.js` 都一致（以前走動畫面本來就點不到，但清單和工具還算得到）。index.html 的 `itemRoomOpen(it)`。
     照舊不管的：找不到那個房間 id 的證物、用 `world[地點].spots` 或 `it.area` 搬到別處的證物、自己寫走動場景的地點（第 1、2 集）、沒有分房間的地點。
  另外：`balance.js` 會改 `ph.clock.end`，所以 `clock` 如果是 getter，每次要回傳同一個物件。

- `labels.js [截圖資料夾]`：場景裡的字（招牌、攤位名、門牌）的檢查，最後印 `SCENE LABELS PASS`。
  走動畫面的畫布只有 240×135，場景自己用 `fillText` 寫的中文會糊掉。改成寫在設定裡，引擎在每一種畫面各用適合的方法寫：
  `EPn.world[地點].labels = [{ room:"stalls", x:20, y:30, text:"阿月豆花", size:7, color:"#f8d868", bold:true }]`
  - `x`、`y` 是那個房間場景裡的座標（跟證物的 `hot` 一樣，x 0–191、y 0–107），跟 `fillText` 一樣是「字的左邊、基線」。`align:"center"`／`"right"` 可以改成置中、靠右。
  - `room` 不寫＝第一個房間；`size` 不寫＝6；`color` 不寫＝深色；`font` 不寫＝`sans-serif`（可以寫 `"monospace"`）。
  - `when:(ph, opt) => 要不要顯示`；`color` 也可以寫成 `(ph, opt) => 顏色`（`opt` 是那個房間的 opt，例如燈亮不亮）。整個 `labels` 也可以寫成 `(ph, has) => 陣列`。
  - 走動畫面：用 HTML 疊在畫布上（world.js 的 `sceneTexts`，`.wtext`）。戶外的房間一直看得到；室內的房間要走進那棟建築才出現（跟外牆一起淡入淡出）。
    戶外場景在陰天、下雨、晚上會被染暗，字的顏色也跟著染（`tint:false`＝不要，例如場景自己已經把顏色調亮的那幾集）。
    HTML 在畫布上面，所以人走到字前面的時候，被擋住的那幾個字會先收起來（一個字一個字算），走開就出現。字盡量放在比人頭高的地方（場景 y 小於 55 左右）。
  - 放大的場景、問話的背景、監視器、重現：`PX.draw`／`PX.play` 畫完場景、還沒畫人的時候，直接寫在畫布上（那裡是 4 倍的細格，看得清楚）。
    所以場景自己就不要再寫這些字了。同一個場景被好幾個房間用的話，用第一個有寫 `labels` 的房間的字。重現裡要看天數的 `when`，請在重現的 `opt` 寫 `phase`。
  - 還沒搬過來的舊場景：場景裡可以看 `PX.inWorld`，畫在走動畫面的小畫布上時是 `true`（那時候跳過自己的 `fillText`，其他畫面照舊）。
