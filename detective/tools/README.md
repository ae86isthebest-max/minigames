# 製作檢查工具（不是遊戲的一部分）

先在 `detective/` 開一個本機伺服器：`python3 -m http.server 8765`，再用 node 執行（需要 playwright）。

- `lint.js`：兩集的資料檢查。問題／證物引用的 id 是否存在、每樣東西有沒有區域、每個區域有沒有東西、每天的時間夠做多少。最後會列出每條推理題「看到哪一樣線索就會出現」，要人工確認每一樣單獨都足以知道題目的前提。
- `lint2.js`：「出示……」的問題有沒有設前提、哪些證物會過期。
- `arr.js`：只靠畫面箭嘴，能不能走到每一個區域。
- `arctest.js`：跨集記憶（arc.js，主線用）：這一集查到、下一集記得，前情提要兩個版本。最後要印出 ARC TEST PASS。
- `slots.js`：三個存檔位（arc.js 的 SLOT）各自獨立、舊進度變成存檔 1、刪除只刪那一個；換存檔要先確認（`slotUse` 是 async，腳本裡要 `await`）；存檔碼（`SLOT.code`／`SLOT.load`）匯出再還原內容一樣、亂貼的碼不會弄壞進度。最後要印出 SLOT TEST PASS。
- `balance.js <案件編號> [設定]`：多日案件的平衡統計。每天「全部做完要幾分鐘 ÷ 那天有幾分鐘」（一定要 ≤ 2，目標 ≤ 1.8）、每個人當天問得到幾題、照正常玩法一輪看得到多少。標準：每個人每天肯回答 6–10 題、至少是當天問得到的一半；時間至少夠做完一半。可以用第二個參數試別的數字，或用 `"from":n` 模擬「玩到第 n 天才換新規則」的舊存檔。
- `glint.js`：走近才閃（world.js 的 nearYou／glint：還沒看過的證物和小細節，只有主角在同一個區域或 40 格內、同一層樓才閃）、小東西的點擊範圍（至少一根手指大），以及人擋在東西前面的情況（閃光畫在人上面，並移到沒被擋住的位置；點在人身上＝找人，整個被擋住的東西先看東西）。最後要印出 GLINT TEST PASS。
- `backup.js`：自動備份（arc.js 的 BACKUP），用假的 `window.claude` 模擬試玩卡的雲端資料：備份上去、儲存空間不見了自動拿回來、備份比較多時先問、自己刪的不會跑回來、連不上不當機、網站版安靜略過。最後要印出 BACKUP TEST PASS。真的試玩卡要宣告 `capabilities:{ db:{}, user:{} }` 才有備份；有沒有開到，看首頁存檔列是不是寫「☁ 自動備份開著」。
- `rq.js`：推理題一打開就算一次機會（平常蓋著、離開再蓋起來、第一次全對才有 S）。最後要印出 RQ TEST PASS。
- `ep1.js`、`play2.js`：照最佳路線玩第一、二集，要拿到 S。
- `poses.js <輸出資料夾>`：人物動作總表（poses-front / poses-hands / poses-side.png）。改了 pixel.js 的人物就跑一次，用眼睛看：每個動作左右手、面向左右對不對，放大以後有沒有變形。
- `animsheet.js`：重播／監視器動畫的逐格總表。`CASE=案件id node tools/animsheet.js <輸出資料夾> [動畫id或場景名|-] [每段幾格=4] [每格寬=288]`，
  環境變數 `BEATS=4-7` 只看其中幾段、`CROP=x,y,w,h` 放大一小塊（192×108 的座標）。一列是一段字幕，由左到右是這一段的 12%、40%、68%、97%。
  每一段都要用眼睛對：動作和字幕／證物對不對、用哪隻手、有沒有沿著樓梯一級一級走、人有沒有穿過桌子或屍體、進門是不是背面走進去。
  某一段有 `scene`（換場景）的話，左上角會印出場景名。也會自動警告：打錯的姿勢／物件名字、斜著走卻沒有宣告 `stairs`、直上直下卻沒有宣告 `ladders`。寫法見 pixel.js 的「姿勢字串」和 PX.play 的說明，第 1、2 集（case1_art.js、case2_art.js）是範例。

每次更新試玩版之前全部跑一次。
